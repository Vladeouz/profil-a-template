  - Bagian baru **Pola lanjutan presentation**: daftar berpagination dengan filter (filter di setiap state, penghitung generasi `_generation` untuk membuang hasil request lama, item yang tidak cocok dibuang); aksi di daftar dengan kegagalan sebagai SnackBar (`Loaded.actionFailure` + `listenWhen`); teks kegagalan khusus fitur di field (konstanta di widget form, dipilih dari `failure.code`); varian form untuk fitur tanpa `GET` per item (tanpa `Loading`/`LoadFailed`, rute ubah tanpa `extra` di-redirect ke daftar).
  - Pohon `lib/core/` memuat `widgets/` beserta aturan widget bersama (fitur tidak mengimpor widget fitur lain; pindahkan ke `core/widgets/`, jangan disalin). Rujukan `FailureView`/`LoadMoreFooter` di bagian notes menunjuk `core/widgets/`. Bagian Teks UI (D-03), Form notes, Test Flutter, dan "Menghapus fitur contoh notes" (langkah 4: `core/widgets/` tetap ada) diberi rujukan silang.

## Keputusan yang diambil sendiri

- **Pola tanpa file contoh ditulis dengan potongan kode generik**, bukan dengan menambah filter, keunikan, atau aksi ke fitur notes. Alasan: `CLAUDE.md` melarang menambah perilaku ke notes, daftar `files` task tidak mencakup API notes, dan kriteria menyebut "bila ada". Bila diinginkan, notes bisa diperluas dalam task tersendiri agar setiap pola punya file contoh; konsekuensinya notes menjadi lebih besar untuk ditiru dan dihapus.
- **`LoadMoreFooter` menerima `loadingMore` dan `failure`, bukan state Cubit**, agar `core` tidak bergantung pada fitur. Nama `failure` (bukan `loadMoreFailure`) karena konteksnya sudah jelas dari nama widget.
- **Test sendiri untuk widget di `core/widgets/`**, walaupun test halaman notes sudah mencakup perilakunya, karena test halaman notes ikut terhapus saat notes dihapus.
- **Aturan "fitur tidak mengimpor widget fitur lain; pindahkan ke `core/widgets/`, jangan disalin"** ditambahkan. Di `daftar-belanja`, widget disalin ke fitur shopping karena memindahnya berarti menyentuh notes; kini widget sudah di `core`, jadi proyek baru tidak perlu menyalin.
- **Endpoint aksi non-CRUD diberi aturan path dan idempotensi** (`POST /v1/<resource>/<aksi>`, `200` dengan jumlah `0`), selain penamaan `<Operasi>Result` yang diminta, karena keduanya diputuskan bersamaan di log T-002 `daftar-belanja` dan berguna untuk pola yang sama.
