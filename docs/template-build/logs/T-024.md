## Ringkasan

Perbaikan dari uji agent `daftar-belanja`. Di sana, hasil `pnpm init-project` belum di-commit saat sesi agent pertama sehingga tercampur dengan task (log T-001 di repo itu). Selain itu, `.env` belum ada saat verifikasi manual (log T-004), dan perintah Flutter web tanpa flag incognito membuat login gagal (log T-005, T-006).

- **`scripts/init-project.mjs`**: output akhir kini berisi 6 langkah wajib dan berurutan (fungsi `nextSteps`), masing-masing dengan perintahnya:
  1. Buat `.env` dari `.env.example` (`copy`, atau `cp` di Git Bash/Linux), timpa bila sudah ada.
  2. `pnpm prereq`.
  3. `docker compose up -d --wait`. Port harus bebas dari layanan proyek lain; bila volume lama, `docker compose down -v` dulu.
  4. `pnpm check` sampai `Semua 7 langkah OK.`
  5. Commit hasil inisialisasi (`git add -A`, `git commit -m "chore: inisialisasi proyek <nama> dari template"`) sebelum sesi agent pertama.
  6. Isi `docs/PRD.md` dan `docs/TASKS.md`, commit ke `master`, lalu mulai sesi agent.
- **`README.md`** › Memulai proyek baru dari template: daftar 6 langkah yang sama dengan blok perintahnya, plus `corepack enable` sebelum `pnpm install`.
- **`docs/conventions.md`**: bagian baru "Memulai proyek dan log task" berisi tiga aturan:
  - urutan wajib di atas, dengan aturan bahwa script dan README diubah bersamaan;
  - agent memulai sesi hanya dari working tree yang bersih;
  - setiap langkah verifikasi manual ditulis lengkap, dimulai dengan persiapan (`.env`, `docker compose up -d --wait`, `db:migrate` bila perlu, `pnpm --filter api dev`), dan memakai perintah Flutter web lengkap dengan `--web-browser-flag=--incognito`.
- **`CLAUDE.md`**:
  - Di awal sesi: periksa working tree bersih. Perubahan yang belum di-commit dilaporkan ke user, tidak di-commit agent.
  - Di Verifikasi: langkah manual selalu dimulai dengan persiapan `.env` dan memakai flag incognito, dengan rujukan ke konvensi.

## Keputusan yang diambil sendiri

- **Langkah 6 (isi PRD/TASKS lalu commit) ditambahkan** setelah commit inisialisasi. Kriteria hanya menyebut commit hasil inisialisasi, tetapi `docs/PRD.md` yang diisi dan belum di-commit akan memicu masalah yang sama di sesi agent pertama (di `daftar-belanja`, PRD dan TASKS juga masih untracked).
- **`.env` disalin di langkah 1, sebelum `pnpm prereq` dan `docker compose up`.** Compose mengambil `POSTGRES_DB` dan `FIREBASE_PROJECT_ID` dari `.env`. Langkah ini meminta `.env` ditimpa bila sudah ada, karena nilainya ikut berubah oleh init.
- **Peringatan port bentrok dimasukkan ke langkah 3**, karena dua kali terjadi saat uji (T-023, T-024): proyek turunan memakai port yang sama.
- **Langkah dicetak dari satu fungsi `nextSteps`**, dengan komentar bahwa README harus diubah bersamaan. Tidak ada test yang membandingkan keduanya otomatis; cara paling sederhana.
- **Aturan working tree bersih di `CLAUDE.md`**: agent melapor dan tidak meng-commit sendiri. Di `daftar-belanja`, agent meng-commit hasil inisialisasi ke `master` (atas persetujuan user), padahal aturannya agent tidak menyentuh `master`.
- **Persiapan manual ditulis lengkap di setiap log**, bukan merujuk log sebelumnya, agar setiap log bisa diikuti sendiri.

## Kendala

- **`corepack enable` gagal di mesin ini** (`EPERM … C:\Program Files\nodejs\pnpm`): perlu hak admin karena Node terpasang di `Program Files`, dan pnpm 12.6.0 sudah aktif. Langkah README tetap dipertahankan karena dibutuhkan di mesin baru. Usulan: README menyebut bahwa `corepack enable` perlu terminal admin bila Node terpasang di `Program Files`.
- **Peringatan Pub cache di `pnpm prereq`.** Salinan uji ada di folder scratchpad di drive C:, sedangkan pub cache ada di `D:\dev\.pub-cache`. Proyek yang dibuat di `D:\dev` tidak akan mendapat peringatan ini. User memilih menerima peringatan ini daripada mengulang uji di `D:\dev`.
- **Test acak `notes-schema.int.test.ts` › updated_at diperbarui lewat Drizzle, created_at tetap** gagal sekali: `expected 1791622568217 to be greater than or equal to 1791622568218`.
  - Dugaan penyebab: `updated_at` awal diisi `defaultNow()` (jam PostgreSQL di VM Docker), sedangkan nilai setelah update diisi `$onUpdate(() => new Date())` (jam host Node). Selisih jam 1 ms membuat nilai baru bisa lebih kecil. Ini masalah di `columns.ts`, bukan hanya di test: di produksi pun `updated_at` bisa mundur sedikit bila jam API dan database berbeda.
  - Tidak diperbaiki di sini karena di luar cakupan T-024. Usulan task: `$onUpdate` memakai `sql\`now()\`` (jam database) agar `created_at` dan `updated_at` berasal dari sumber yang sama, lalu test dijalankan berulang untuk membuktikan.
- **Layanan Docker `daftar-belanja` dihentikan sementara** (port sama), atas persetujuan user. Urutannya:
  1. Uji salinan.
  2. `docker compose down -v` di salinan.
  3. Layanan template dinyalakan untuk `pnpm check`, lalu dihentikan.
  4. Layanan `daftar-belanja` dinyalakan lagi (ketiganya healthy).

  Akun Auth Emulator `daftar-belanja` hilang karena hanya disimpan di memori. Folder salinan sudah dihapus.
