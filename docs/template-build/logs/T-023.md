## Status

Selesai (2026-10-10). Branch: `fix/t-023-diagnosis-error` (dari `master` setelah T-022).

## Ringkasan

Tiga perbaikan dari uji agent `daftar-belanja` (log T-006 dan T-007 di repo itu), agar kegagalan yang tampil ke user sebagai teks umum bisa didiagnosis.

- **Flutter web dengan `--web-browser-flag=--incognito`.** Semua perintah Flutter web (README, `apps/app/README.md`, `docs/conventions.md` bagian Config) memakai flag ini. Penjelasan penyebabnya ada di poin baru "Lingkungan Flutter dan Android": profil Chrome antar-run menyimpan sesi Firebase, sesi itu divalidasi ke Google di dalam `Firebase.initializeApp()` sebelum `useAuthEmulator`, lalu SDK menolak pindah ke emulator dan semua request auth ditolak Google karena API key dummy. README menjelaskannya singkat dan merujuk ke konvensi.
- **`logFailure`** (`apps/app/lib/core/error/failure_log.dart`, sama dengan `daftar-belanja`) mencetak `Failure <code>: <message> (fields: …)` lewat `debugPrint` hanya di mode debug. Fungsi ini dipanggil di dua batas tempat exception menjadi `Failure`: `apiCall` dan `FirebaseAuthRepository._failure` (login, daftar, logout). Mapper tidak diubah.
- **Penolakan token di API dicatat.** `TokenVerifier.verify` kini mengembalikan `{ ok: true, identity }` atau `{ ok: false, reason }` (sebelumnya `VerifiedIdentity | null`). `reason` adalah `FirebaseAuthError.code`. Middleware `authenticate` mencatat `warn` `rejected ID token` dengan `{ reason }` saja; token, klaim, dan `message` firebase-admin (bisa mengutip klaim `aud`/`iss`) tidak dicatat. Perilaku HTTP tidak berubah.
- Helper test API baru `test/helpers/capture-logger.ts` (dipindah dari `logger.test.ts`, yang kini memakainya).

## Keputusan yang diambil sendiri

- **`TokenVerifier.verify` mengembalikan union `{ ok, … }`, bukan melempar error khusus atau tetap `null`.** Middleware butuh alasan penolakan, dan logger ada di middleware (`c.var.log`), bukan di verifier. Union membuat penolakan tetap nilai biasa (bukan exception), dan error yang benar-benar tak terduga tetap dilempar (→ `500`). Akibatnya semua stub verifier (`rejectAllTokens`, `export-openapi.ts`, test) ikut diubah.
- **Hanya `FirebaseAuthError.code`, bukan `message`.** Pesan firebase-admin untuk `aud`/`iss` salah mengutip nilai klaim token (dijaga test). Kriteria meminta "tanpa token atau isinya".
- **Header tidak ada atau bukan Bearer tidak dicatat.** Kasus ini tidak melibatkan firebase-admin; mencatatnya hanya menambah log dari request anonim (bot, health check salah alamat). Log `request completed` dengan status `401` sudah ada.
- **Level `warn`** (sesuai kriteria) menggantikan log `info` lama tanpa alasan.
- **Integration test di `me.int.test.ts`**, selain unit test, agar kode yang dicatat terbukti kode asli firebase-admin dari Auth Emulator, bukan nilai buatan test.
- **`captureLogger` dipindah ke `test/helpers/capture-logger.ts`**, karena kini dipakai tiga file test; `logger.test.ts` memakainya alih-alih salinan lokal.
- **Penjelasan incognito disalin dari konvensi `daftar-belanja`**, tanpa menjalankan ulang reproduksi bug di template. Stack-nya sama (Flutter 3.47.5, `firebase_auth` 6.7.0, `main.dart` yang sama), dan reproduksinya sudah tercatat di log T-006 repo itu. Konvensi menyebut sumbernya.
- **Isi log `logFailure`** sama dengan `daftar-belanja`: kode, `Failure.message`, dan nama field (bukan isi `FieldIssue`).
