# T-010 Port `PushSender` dan `FileStorage` dengan adapter

## Status

Selesai. Branch: `feat/t-010-ports`.

## Ringkasan

- `apps/api/src/core/ports/push-sender.ts`: port `PushSender.send({ token, title, body, data? })` → `{ status: 'sent', messageId }` atau `{ status: 'invalid-token' }`; kegagalan lain dilempar.
- `apps/api/src/core/ports/file-storage.ts`: port `FileStorage` (`save` menimpa, `read` → `{ data, contentType }` atau `null`, `delete` idempoten) dan `assertValidFilePath()` / `InvalidFilePathError` yang dipakai semua adapter.
- Adapter di `core/ports/adapters/`:
  - `fake-push.ts`: mencatat salinan pesan di `sent`, `markInvalid(token)`, `clear()`.
  - `fcm-push.ts`: `createFcmPushSender(messaging)` memetakan pesan ke `{ token, notification, data }` firebase-admin; `messaging/registration-token-not-registered` dan `messaging/invalid-registration-token` → `invalid-token`.
  - `fake-storage.ts`: `Map` di memori dengan salinan buffer, `paths()`.
  - `firebase-storage.ts`: `createFirebaseFileStorage(bucket)` lewat firebase-admin (`save` sekali kirim, `read` = `download` + `getMetadata`, 404 → `null`, `delete({ ignoreNotFound: true })`).
- `core/ports/create-ports.ts`: `createPorts(env, firebaseApp)` memilih adapter dari `PUSH_ADAPTER` dan `STORAGE_ADAPTER`; klien firebase-admin hanya dibuat untuk adapter yang dipakai.
- Env baru: `PUSH_ADAPTER` (`fake`/`fcm`, default `fake`), `STORAGE_ADAPTER` (`fake`/`firebase`, default `fake`), `FIREBASE_STORAGE_BUCKET` (wajib bila `STORAGE_ADAPTER=firebase`), `FIREBASE_STORAGE_EMULATOR_HOST` (`host:port`, ditolak saat `NODE_ENV=production`).
- `server.ts` memanggil `createPorts` dengan app firebase-admin yang sudah ada, mencatat adapter di log `API listening`, dan memberi peringatan bila adapter `fake` dipakai di produksi. `createApp` menerima `ports` lewat `AppDeps` (belum dipakai fitur mana pun); `createTestApp()` memakai adapter palsu.

## Keputusan yang diambil sendiri

- **`send` mengembalikan `invalid-token` alih-alih melempar** untuk token mati, karena itu kasus rutin yang perlu ditangani pemanggil (hapus token), berbeda dari kegagalan jaringan atau kredensial yang tetap dilempar.
- **Port push untuk satu token per panggilan**, tanpa multicast atau topic. Paling sederhana; proyek yang butuh bisa menambah metode di port.
- **`FileStorage` tanpa signed URL atau daftar file.** Signed URL butuh kredensial service account yang tidak ada di emulator; ditambahkan proyek yang membutuhkannya.
- **Validasi path di port (`assertValidFilePath`)** dan dipanggil setiap adapter, agar adapter palsu dan Firebase menolak path yang sama dan path dari input user tidak bisa keluar dari prefix-nya.
- **Default `fake` untuk kedua adapter, tidak ditolak di produksi, tetapi diberi log `warn`.** Menolak `fake` di produksi akan memaksa proyek yang tidak memakai Storage tetap menyiapkan bucket (Storage kini butuh paket Blaze); peringatan di log cukup untuk menandai salah konfigurasi.
- **`FIREBASE_STORAGE_BUCKET` tanpa default** (tidak diturunkan dari `FIREBASE_PROJECT_ID`), karena project baru memakai `<id>.firebasestorage.app` sedangkan project lama `<id>.appspot.com`.
- **`.env.example` memakai `STORAGE_ADAPTER=firebase`** dengan Storage Emulator agar development lokal memakai jalur sungguhan; `PUSH_ADAPTER=fake` karena tidak ada emulator FCM.
- **`AppDeps.ports` ditambahkan sekarang** walau belum dipakai, agar fitur berikutnya merakit use case dengan port di `createApp` seperti repository.

Usulan untuk `docs/conventions.md`: sudah ditambahkan (bagian "Port push dan storage" dan bagian Env), termasuk pola untuk layanan luar baru.

## Kendala

- Tidak ada yang menghambat. Catatan: firebase-admin membaca `FIREBASE_STORAGE_EMULATOR_HOST` saat `getStorage()` pertama dipanggil dan menyalinnya ke `process.env.STORAGE_EMULATOR_HOST` (global proses); test int memeriksa nilai itu agar tidak diam-diam memanggil GCS sungguhan.
- `.env` milik user tidak diubah. Tanpa variabel baru, server memakai adapter `fake` (default). Untuk memakai Storage Emulator saat development, salin baris `FIREBASE_STORAGE_EMULATOR_HOST`, `FIREBASE_STORAGE_BUCKET`, `PUSH_ADAPTER`, dan `STORAGE_ADAPTER` dari `.env.example`.
